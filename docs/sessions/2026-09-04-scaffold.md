## Claude

My pick: knock out the local tray tweaks first, then start the Japanese dictionary app as the real project.

**Why the dictionary app first**
- It is the one you would use every day. You already run fcitx5 with mozc and a WaniKani module in the bar, so a native Jisho plus Wadoku lookup slots straight into your existing routine.
- It needs no server. JMdict, KANJIDIC, KanjiVG and Tatoeba are all free downloads, so the app works offline and the tests can run against real data without a fake backend.
- The gap is real. Nothing on Linux shows German and English glosses side by side with pitch accent, and SlobDict only gives plain headword lookup.
- It reuses your yubioath-gtk and Den Mail patterns directly: Python, libadwaita, pytest, autopilot screenshots in headless cage.
- One thing to check early: the Wadoku license allows local use but may restrict redistribution, so the app should download and import the XML on first run rather than ship it.

**Why Paperless second, not first**
- It is the largest ecosystem gap, and the REST API is well documented, so it would be a strong public project.
- But it only pays off if you actually run a Paperless-ngx instance, and it needs the fake-server test setup from Den Mail rebuilt for a new API. Good follow-up once the dictionary is usable.

**Why Home Assistant last**
- Butler already covers the daily need well enough, and a native entity UI is a much bigger surface than the other two. Low return for the effort right now.

**The local tweaks**
- Tray icons, the ML4W icon, and a custom theme color set are each an evening of work in the Quickshell config. Worth doing first as quick wins, and they are independent of the app choice.

A sensible first milestone for the dictionary app: a `felsenuboot/kotoba` style repo with a JMdict importer into SQLite and a search window that shows word, reading, and English plus German glosses. Kanji details, strokes, examples and pitch accent come after that.

## Claude

Tango is scaffolded in Rust, pushed to a private repo at `github.com/felsenuboot/tango`, and CI is green on all four jobs.

**What it does right now**
- Downloads JMdict from inside the app, or imports a local copy, into SQLite. The real file imported 218,700 entries in about 13 seconds in the headless test.
- Searches headwords and readings for kana or kanji input, and glosses for English or German input. Exact matches and common words come first.
- Shows an entry with headword, readings, alternative spellings, and every sense with parts of speech and glosses per language.
- Adaptive split view that collapses on narrow windows, light and dark theme, preferences for colour scheme and preferred gloss language.
- Keyboard shortcuts: Ctrl+F or slash for search, Ctrl+I import, Ctrl+comma preferences.

**Verified**
- 13 unit tests pass, clippy with `-D warnings` and rustfmt are clean, locally and in CI on Ubuntu 24.04.
- End-to-end headless run in cage with the real JMdict: import, search for 猫, correct top result, screenshot. That screenshot is in the README.

**Two things worth knowing**
- The ftp.edrdg.org host has a broken TLS certificate, so the download URL uses www.edrdg.org instead.
- JMdict ships German, Dutch and French glosses as separate senses, not alongside the English ones. A merge step is the first roadmap item, since the side-by-side view was the point.

**For learning Rust**, start with `docs/DEVELOPMENT.md`. It has a reading order through the files and explains the five idioms you will keep meeting: builders, `Rc<RefCell>` state, weak references in callbacks, channels for worker threads, and prelude traits.

To run it against your real config:

```
cd ~/ghq/github.com/felsenuboot/tango && cargo run
```

Or `./install.sh` for a release binary in `~/.local/bin` with a desktop entry. The idea in ideas.md is marked as started, and the Python draft was discarded before anything was committed.
