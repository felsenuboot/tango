# PR #158: Flatpak composer compatibility

The failing job 106081853188 in run 35512167339 compiled and installed Tango,
then the Ubuntu 22.04 native Builder invoked `appstream-compose` in GNOME 49.
That SDK uses `appstreamcli compose`. Host AppStream packages do not supply
executables to the SDK sandbox. Upstream Builder 1.4.4's `builder-manifest.c`
uses the new composer.

Use the stable org.flatpak.Builder application for both Fedora and CI, with
its default wrapper (which locates the host Flatpak executable). Keep GNOME 49,
the Rust extension, offline crate sources and sandbox permissions unchanged.
Log Builder version/commit, check SDK composer availability before compilation,
and reject absent/empty bundles. CI now installs the actual bundle, loads the
runtime executable and checks desktop/icon exports and composed metadata before
uploading. Nothing is published to Flathub or released.

Local validation: Cargo source-list consistency, Bash syntax, workflow YAML
parsing and `git diff --check` passed. Full build attempt exits with missing
Flatpak. Package installation failed because the environment cannot setgroups /
change package-manager identities; unprivileged user namespace creation also
fails writing uid_map. Cargo, rustfmt, Clippy and ShellCheck are absent. These
checks must run on GitHub's Linux runner; no local bundle success is claimed.

Static integration inspection: desktop Exec=tango %U, icon name and Rust APP_ID
match the manifest ID. Import/export uses gtk::FileDialog and reads/writes the
returned local file; portal document grants are needed and no broad home access
is granted. libsecret store/lookup/clear uses Secret Service, for which the
manifest grants org.freedesktop.secrets access. The version path exits before
creating GTK state or opening databases.

Graphical tests NOT EXECUTED: GNOME app-grid launch/icon, Wayland/X11 display,
portal chooser cancellation and import/export outside the sandbox, keyring
unlock/store/restart/lookup/delete, and saved preferences/list persistence.
There is no Fedora/GNOME session, display, portal or keyring here. Source review
and the headless bundle check do not establish these behaviors. On Fedora use a
throwaway user/profile and dummy token for keyring checks; do not expose real
account tokens in test logs. Follow docs/FLATPAK.md for the manual checklist.

The first updated CI run selected Builder 1.4.9 and passed the SDK composer
preflight, but its host-command wrapper needed a session D-Bus (absent on the
headless runner). Run the build under dbus-run-session in CI; Fedora GNOME
already has a user session bus.
